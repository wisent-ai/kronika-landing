Docs/CLI/onboarding
Kronika CLI command

kronika onboarding

Present or move the first-use journey from the command line: the same screens, progress and first-success fact the graphical importer walks, read from Kronika's own packaged journey and kept under Kronika's own state.

Invocation

kronika onboarding [--advance | --skip | --reset | --status] [--json]

With no action the current screen is shown and an attempt is started when none exists. The four actions are exclusive; the last one named wins.

Inputs and options

OptionEffect
--advanceMoves to the next screen along the journey's own transitions.
--skipLeaves the journey without completing it; the workspace stays usable.
--resetDiscards the recorded attempt and replays the journey from its entry screen.
--statusReports an existing attempt without starting one; with none, the entry screen as not started.
--jsonPrints the view below as JSON instead of the text a person reads.

No Brama configuration is read. When KRONIKA_STADO_INTEGRATION_TOKEN and the control-plane origin are set, progress is also mirrored to the control plane; without them local progress is authoritative and nothing is refused.

Output and state

Stdout is the current screen: status (not_started, in_progress, completed or skipped), screenId, screenKind, step of stepCount, title, body, actions, the screen's command and expected result when it declares them, completedScreenIds and firstSuccessFact. Completion is recorded only when the fact is observed — kronika init adopting or recognising a workspace — never by viewing a screen. Progress is written under Kronika's state directory; a persisted attempt is resumed only when it belongs to this journey version and this installation, otherwise a fresh attempt starts.

Exact refusals

  • onboarding bundle envelope is invalid, onboarding bundle identity is invalid, onboarding bundle integrity is invalid, onboarding screen graph is invalid, onboarding screen is invalid, onboarding entry screen is missing, onboarding fallback is missing, onboarding transition is invalid — a journey bundle that does not validate; the packaged canonical journey is used in its place where one is available.
  • onboarding progress points at an unknown screen — a recorded attempt names a screen the journey no longer has.
  • onboarding control plane is unavailable, onboarding control plane URL is invalid, onboarding control plane rejected the request — the mirror to the control plane, reported when it was configured and did not answer; local progress stays authoritative.

Any refusal is written to stderr as kronika: <message> and exits 1; an unknown option is Unknown option: <flag> and exits 2 with the usage.
