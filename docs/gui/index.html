Kronika local workspace

Graphical existing-project importer

kronika gui serves an accessible browser workspace from the installed package. It prints the exact session URL and does not open a browser. The workspace adopts existing Markdown through initializeDocumentationWorkspace, the same exported TypeScript function called by kronika init. There is one manifest format and one persistence implementation.

Start the workspace

kronika gui --repo /path/to/project
# Select a fixed loopback port when needed:
kronika gui --repo /path/to/project --port 4173

Open the printed URL exactly, including its token fragment. By default the operating system assigns an available port. The server binds 127.0.0.1 only; it never opens a consent window, model route, deployment, or validation process. Stop the foreground command to end the session.

Browser file controls cannot disclose a real local path, so the local workspace accepts explicit repository-relative selections rather than uploading document copies. The selected files remain at their original paths; directories are traversed by the core importer, duplicate Markdown paths collapse to one identity, source declarations are de-duplicated and sorted, and no document body crosses the HTTP boundary.

Results and readback

The result keeps imported, unchanged, conflicting, and rejected paths separate. Conflicts include the retained manifest path and the reason replacement was refused. Rejections include the source-derived path error. After an imported or unchanged result, the server loads the exact persisted manifest with loadSyncManifest; the workspace renders its schema version and every accepted document, evidence source, and standing instruction. It never infers success from form state.

  • Imported — the validated manifest was atomically persisted and read back.
  • Unchanged — the retained manifest is structurally identical; no write occurred.
  • Conflict — the retained manifest differs and remains untouched. Review its readback, then explicitly select replace if appropriate.
  • Rejected — no project was accepted; the path and reason explain the refusal.

The full adoption behavior and exact selection refusals are the kronika init contract. GUI request and session refusals are listed in the runbook.

Local session security

The GUI is a local administrative surface, not a network service. Every API request must carry a 256-bit per-process token. Mutation additionally requires the exact printed origin; every request requires the exact 127.0.0.1:<port> host, preventing alternate-host and DNS-rebinding use. JSON bodies are capped at 65536 bytes before parsing. The frontend uses DOM text nodes for repository paths, reasons, and manifest values, and the server applies a self-only content security policy, frame denial, no-referrer policy, and no-store responses.

Persistence boundary

Import can write only the selected manifest, atomically, after the core importer validates the entire repository-confined selection. It does not copy or change documents, write sync state, call Brama, infer or generate prose, execute Git or package scripts, deploy anything, or invoke tests and validation. Later kronika sync consumes the same manifest.
