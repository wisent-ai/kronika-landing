Runbook

Kronika failed — what does the sentence mean, and what do you check? Every failure is one line on stderr, kronika: <message>, exit status 1, or 2 with the help when the command line itself is refused; sync additionally reports per-document failed outcomes and exits 1 when any document failed. Every sentence below exists verbatim in src/ and the marked ones were captured by running the CLI.

Flags and commands

A refused invocation exits 2 and prints the help after the refusal. Each refusal is one line: the sentence below, then : and why it was refused for this command line, then ; and what to write instead.

Sentence Causes it names / fix it states
Unknown command: <word> † the first word is none of check, write, sources, sync, init, gui, onboarding, or an option came before any command; put one of those first
<command> does not accept <word> † the option belongs to another command (named), no command has that option (check its spelling), or the word is not an option and the command takes no positional word; the line lists the options the command accepts
<flag> requires a value † the flag is the last word, the word after it is blank, or the word after it is another option (another option cannot supply it); write the value right after the flag
<flag> must be a positive integer † the value is not a number, not a whole number, zero, negative, or above 9007199254740991; write a whole number of 1 or more
--port must be between 1 and 65535 † the port is above TCP's 16-bit maximum; choose a free port of at most 65535, or omit --port for an operating-system-assigned one
check requires --base <ref> † check has no change to audit without a base; name the commit the change starts from, for example --base origin/main
onboarding accepts one action; --<first> conflicts with --<second> † one run performs exactly one action; run each as its own command
sync --push requires --commit † without --commit sync makes no commit to push; add --commit or leave out --push
Unknown option: <flag> a command lists an option its parser reads no value for; this is a Kronika defect, report it with the message

Starting the CLI and the graphical workspace

The quick start runs npm install and npm run build; until both exit 0 there is no dist/src/cli.js to run, so the first error to read is the build's own. These refusals exit 1 without the help:

SentenceCauses it names / fix it states
Repository <path> (from --repo) cannot be used †nothing exists at the path (ENOENT), a component of it is a file (ENOTDIR), this user may not look it up (EACCES/EPERM), a symbolic-link loop (ELOOP), a path too long (ENAMETOOLONG), or another operating-system refusal quoted whole; pass --repo an existing repository directory you can read. sources and gui refuse this first, gui before it opens a socket; check and write after their Brama configuration is read
Repository is not a directory: <path> †--repo names a file; pass the repository directory, not a file inside it
the graphical workspace cannot listen on 127.0.0.1:<port> †another process listens there (EADDRINUSE; lsof names it), the port is refused to this user (EACCES; ports below 1024 are privileged), no loopback interface (EADDRNOTAVAIL), no file descriptor left (EMFILE/ENFILE), or another code quoted whole; each states its fix, and omitting --port lets the operating system choose a free port
the graphical workspace cannot start: Node reported its listening socket as …Node returned no TCP address for a socket it opened; a Node or Kronika defect, report it with node --version

The startup qualification node tests/startup/cli.mjs builds the checkout with npm run build, runs init, sources and gui against an isolated project, then runs each cause marked † in the two tables above, and the two Brama environment refusals below, as a real process and requires its sentence, cause, fix and exit status. The causes that cannot be staged without damaging the machine (EADDRNOTAVAIL, EMFILE, ENFILE, a socket without a TCP address, the parser defect) are not run. Declare KRONIKA_TEST_SOURCE_REVISION (the files run must be exactly that commit), KRONIKA_TEST_SUCCESS_EXIT, KRONIKA_TEST_USAGE_EXIT and KRONIKA_TEST_OPERATIONAL_EXIT. Commands, outputs and exits stay under .build/startup/<run>/report.json; a privileged port this user may bind is listed there as unreproduced, not passed.

Environment

Sentence Meaning / fix
BRAMA_URL is required † check/write/sync ask a model; the line says whether BRAMA_URL is unset or empty and to export it, or to run sources, which needs no model. init, gui, sources, onboarding, and help do not read it

Selection refusals

From src/docs/sources.ts and src/docs/writer.ts; all before any network call:

Sentence Meaning / fix
Source is outside the repository: <path> † explicit --source escapes --repo; selection is confined
Source does not exist: <path> † explicit source missing
Symbolic-link sources are not allowed: <path> † symlinks are never followed, even named explicitly
Repository is not a directory: <path> † --repo points at a file
Output is outside the repository: <path> † --output resolves outside --repo; refused by selector and writer both
No safe UTF-8 source files were selected † write with an empty collection — everything was excluded, skipped, or empty; run kronika sources to see why
Source byte limits must be positive library-only: collectSources called with non-positive budgets

Skip reasons (in skipped, not errors): generated, dependency, recording, or private deployment directory · credential or generated lock file · private key or certificate material · larger than <n> bytes · total source limit <n> bytes reached · binary content · not valid UTF-8 text. See sources.

Sentence Meaning / fix
Git commit cannot be resolved: <ref> † --base/--head is not a commit in this repository; check the ref and --repo
Git diff cannot be read for <base>...<head> diff itself failed (shallow clone missing the merge base, corrupt repo)
Git diff is <n> bytes, above --max-diff-bytes <m>; narrow or split the change rather than auditing a truncated diff † deliberate refusal — a truncated diff would audit a change that did not happen. Audit smaller ranges, restrict sync sources, or raise the budget knowingly
Diff byte limit must be a positive integer library-only: checkDocumentation called with a non-positive maxDiffBytes (the CLI validates --max-diff-bytes first)

Transport and Brama answers

From src/docs/model/brama.ts:

Sentence Meaning / fix
fetch failed † Node's own sentence for a network-level failure (refused connection, DNS); Brama never answered. Check BRAMA_URL and reachability
Brama returned HTTP <status>: <detail> † Brama answered an error; <detail> is the server's own error/error.message or the first 1000 bytes of the body — empty response when there was none. 401/403 are credential scope; 5xx is Brama-side
Brama returned no documentation content † 2xx with an empty or unrecognizable completion body

Model output refusals

The model's answer is validated, never trusted. From src/docs/writer.ts (write/rewrite):

  • Brama returned empty documentation — nothing remained after removing one surrounding Markdown code fence and surrounding whitespace
  • Brama returned invalid NUL content

From src/docs/checker.ts (audit verdicts):

  • Kronika returned invalid documentation-check JSON † — the answer was not parseable JSON (one surrounding code fence is tolerated)
  • Kronika documentation check is not an object
  • Kronika documentation check has no boolean passed field
  • Kronika documentation check has no summary
  • Kronika documentation check has no findings array
  • Kronika documentation check contradicts its blocker findings † — passed disagreed with the presence of blockers
  • Kronika finding <i> is not an object / has invalid severity / has invalid code / has invalid document / has invalid sourcePaths / has no message / has invalid requiredChange

A retry is reasonable — these are usually one bad completion. Persistent verdict failures on the same change mean the model selector is too weak or the diff too large to reason over; try a stronger --model.

  • Sync manifest is not valid JSON: <path>

  • Unsupported sync state schemaVersion in <path>

Sync: per-document failed outcomes

Not thrown — reported per document, exit 1, baseline deliberately not advanced, next tick retries the same range:

Detail Meaning / fix
the recorded baseline <sha12> cannot be diffed against HEAD: <git error>. Delete this entry from the state file to re-baseline. † history rewrite or corrupt entry; the remedy is in the sentence
audit did not complete: <message> † the check failed — <message> is any transport/Git/verdict sentence above (captured offline: audit did not complete: fetch failed)
audit found blockers but the rewrite did not complete: <message> the check worked, the write failed; findings are in the outcome, nothing was written

kronika-site (site pipeline)

The separate pipeline reports one JSON object (or, with --text, one path: value line per field) and exits: 2 usage (kronika-site <productRepo> --sources <file> (--standard <writing-standard.md> | --plan <file>) [--out <dir>] [--model <selector>] [--text], and authoring a plan needs --standard, the writing standard its pages follow, or --plan to load one already written), 69 model infrastructure down (brama endpoint unreachable: <url> (<detail>) — a network failure, a response that could not be read, or a gateway-unavailable status, 502, 503 or 504, with its body), 1 any failing stage, 0 all green. An answering endpoint with another bad status is brama at <url> answered HTTP <status>: <body>; an answer without the one required call is brama at <url> answered HTTP <status> without calling <answer>; body: <body> or brama at <url> did not answer by exactly one call of <answer>; body: <body>. See site-pipeline.

† captured by running the built CLI against a toy repository; the remainder quoted from src/.
